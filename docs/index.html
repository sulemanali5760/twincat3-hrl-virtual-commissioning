What you are watching

New pallets arrive on the in-feed, pass the I-point and wait on the transfer station. The emulated material flow computer orders each one into the nearest free place. After every third store it orders the oldest pallet back out, so stores and retrievals alternate like in a real warehouse. Retrieved pallets leave over the out-feed.

The buttons on the left send the faulty telegrams from the interface test, or fail the travel drive mid-job. Watch the PLC answer in the telegram log.

How the PLC program is built

The plant is a tree of nodes. One Cyclic() call on the root runs every node, and each device returns eBusy, eDone or eError to the sequence that commands it.

FB_Hrl                    root mode node
├─ FB_Srm  RBG01          single-cycle sequence
│  ├─ FB_Axis  Travel     simulated trapezoid profile, laser value
│  ├─ FB_Axis  Hoist
│  └─ FB_Axis  Fork
├─ FB_ConveyorZone  Infeed    one standard block,
└─ FB_ConveyorZone  Outfeed   different parameters
FB_Rack           which place holds which pallet, teach-in
FB_MfrInterface   checks every telegram before anything moves

One RBG job, step by step

  1. Travel and hoist drive to the source together. The move takes as long as the slower axis.
  2. The telescopic fork extends 1.10 m into the place (left side negative, right side positive).
  3. The hoist lifts 0.10 m. The pallet is booked off the source place at this moment.
  4. The fork retracts with the pallet.
  5. Travel and hoist drive to the target, still lifted.
  6. The fork extends into the target place.
  7. The hoist lowers. The pallet is booked into the target place at this moment.
  8. The fork retracts. The PLC reports TDON to the material flow computer.

Every telegram is checked first

A transport order only starts the RBG if every check passes. Otherwise the PLC answers TERR with a status code and nothing moves.

The throughput proof

FEM 9.851 measures an RBG by its double cycle: store at P1 (1/5 of the rack length, 2/3 of its height), travel empty to P2 (2/3 length, 1/5 height), retrieve there, return to the station. With travel 3.0 m/s, hoist 1.5 m/s and a 1.10 m fork, the calculation gives 52.4 s, about 69 double cycles per hour. A unit test runs the same two jobs on the simulated RBG and requires the measured time to stay within 5 % of that figure.

What this is not

Everything here is simulated: axes, light barriers and the material flow computer. The PROFINET network, the safety program and the HMI belong to the real plant and are not part of this model. This page is a JavaScript port of the PLC logic for viewing. The TwinCAT project in the repository is the actual program, with 37 TcUnit tests.
